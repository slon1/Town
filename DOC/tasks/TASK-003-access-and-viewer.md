# TASK-003 — Классы доступа, анализ, просмотр слоёв (фаза P3, майлстоун M1)

- **Модель:** Grok (3A–3C), Composer (3D)
- **ADR:** `DOC/adr/ADR-003-access-classes-and-analysis.md` (читать целиком), ADR-001 §5, ADR-002
- **Ветка:** `task/003-access` от `main` (после слияния `task/002-rasterization`; если слияния нет — спросить оператора)
- **Приёмка:** подшаги — самоприёмка; итог — архитектор (M1).
- **Правило test-first** действует для 3B и 3C: отдельный коммит с красными тестами раньше реализации (`[TASK-003/3B-tests]` → `[TASK-003/3B]`).

## Цель

Растр `access` (Obstacle / Roadway / Pedestrian), отчёт о связности карты, окно просмотра слоёв. По результатам оператор видит «где тротуар, где проезжая часть» и принимает M1.

## Вне объёма

Агенты, поля, фреймворк, сцена, меши, исправление данных OSM.

## Подшаги

### 3A (Grok) — закрыть хвосты P2
- Сообщить, **что именно** тот единственный объект с `isTunnel` в районе (вид сущности, `osmId`, ключевые теги: `waterway`/`highway`/`railway`, `tunnel`/`culvert`/`layer`). Если это водоток в трубе под Osloer Straße — отметить в рапорте; это объясняет, почему на пересечении `waterClearedByLinear` мал (28 клеток).
- Проверка площади граничных зданий: пересчитать 22 здания «на границе/вне» растром с `cell = 0,1 м`, ограниченным областью основной сетки, и сравнить с площадью при `cell = 0,5 м` в тех же границах; допуск ±2 %. Это замена сравнения с необрезанным вектором.
- Свести цифры в раздел «Хвосты P2» нового рапорта.
- **Критерий:** оба пункта в рапорте с числами. Самоприёмка.

### 3B (Grok) — классификатор и ассет (test-first)
- Core: `CityAccess : byte`, `AccessClassifier.Classify` и `ClassifyAll` по ADR-003 §2.
- Тесты (красные до реализации): таблица истинности по всем значимым комбинациям битов (в т. ч. `Road|Crosswalk`, `Road|Sidewalk`, `Road|Shared`, `Road|Bridge`, `Rail|Bridge`, `Road|BuildingPassage`, `Sidewalk|BuildingPassage`, `Building`, `Water`, `Barrier`, `Barrier` снят `Gate`, пустая клетка, `Green`); побитовая стабильность `ClassifyAll`.
- `CityBakeAsset`: поля `access` (`byte[]`) и `accessHash`; расчёт в меню Bake (`ZombieCity/City/Bake Grid...`). `ICityMap.GetAccess`. `dataHash` из P2 **не должен измениться** — привести значения до/после.
- **Критерий:** тесты зелёные; `dataHash` не изменился; `accessHash` стабилен между двумя bake. Самоприёмка.

### 3C (Grok) — анализ связности (test-first)
- Core: компоненты по 8-связности с запретом диагонали между двумя угловыми `Obstacle` (ADR-003 §4), для `PedestrianMask` и `ZombieMask`; отчёт (компоненты, острова, эффект переходов, переезды `Road|Rail`, доли классов).
- `CityBakeConfig.islandMinCells` (200) — добавить в `CanonicalBytes()`, обновить золотые хэши настроек («было → стало» в рапорт).
- Тесты (красные до реализации): две области, разделённые стеной, — две компоненты; диагональный проход между двумя угловыми препятствиями запрещён; проход по диагонали при одном препятствии разрешён; остров < порога попадает в список; **синтетические «две улицы + переход»:** без `Crosswalk` — 2 компоненты, с ним — 1, переход помечен как соединяющий.
- Меню `ZombieCity/City/Analyze Access` пишет блок `[City]` и файл `Assets/_Project/City/Baked/analysis_access.md` (таблицы отчёта).
- **Критерий:** тесты зелёные; отчёт по району получен. Самоприёмка.

## Definition of Done — критерии приёмки (проверяет архитектор)

1. Сборка чистая; asmdef по-прежнему ровно два; Core без UnityEngine.
2. Все тесты зелёные (число в рапорте); порядок «тесты → реализация» соблюдён для 3B и 3C (проверка по `git log --stat`).
3. `dataHash` (P2) не изменился; `accessHash` стабилен; оба значения в рапорте. Золотые хэши настроек — «было → стало».
4. Отчёт связности по району приложен целиком (`analysis_access.md` + сводка в рапорте).
5. PNG слоёв: Access и Components видны мне целиком; кропы не меньше 400×400 px.
6. На картах по Access видно: проезжая часть Osloer Straße и боковых улиц — `Roadway`; тротуары и переходы — `Pedestrian`; здания, вода, рельсы — `Obstacle`; двор здания `3583425` — `Pedestrian` (без `Building`).
7. Хвосты P2 закрыты (3A).
8. Рапорт `REPORT-003.md`, ветка запушена, все коммиты в `origin`.

## Заметки
- Район мал, анализ должен выполняться за доли секунды.
- Не использовать порядок `Dictionary`/`HashSet` в выходных данных.
- Если вывод по картинке противоречит ADR-003 (например, переходы не соединяют тротуары) — не править правила, а описать в рапорте с координатами.
