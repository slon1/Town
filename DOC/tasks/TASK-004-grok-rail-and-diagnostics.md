## Контекст

В рапорте REPORT-003 выявлено: рельсовая полоса вдоль Osloer Straße (непрерывно по району) режет карту; в клетках `Road|Rail` (100 шт., x≈86–90, z≈49) перерезана Prinzenallee, пешеходные переходы через рельсы заблокированы; две крупнейшие компоненты (юг ≈ 71 %, север ≈ 23 %) разделены именно этой полосой. Метрика «Crosswalk effect» (116 / 116) неинформативна, потому что тротуарные линии (`Sidewalk`) перекрывают `Road` и связывают тротуары без клеток `Crosswalk`.

## Вне объёма

Окно просмотра (это TASK-005), агенты, сцена, правка OSM-данных, изменение классификатора доступа (`AccessClassifier` не менять).

## Подшаги

### 4A — сведения о рельсах (без изменения кода)
- Для четырёх `Railway` в районе: `osmId`, теги `railway`, `service`, `usage`, `bridge`, `tunnel`, `layer`, `electrified`, длина в районе.
- Для 100 клеток `Road|Rail`: какие `osmId` дорог/путей участвуют; остальные клетки с битом `Rail`: сколько их, какая доля рядом (≤ 1 м) с путями `Walkway`.
- **Критерий:** таблица в рапорте. Самоприёмка.

### 4B — политика рельсов (test-first)
- Тесты (красные до реализации) по ADR-002 v1.2:
  - дорога пересекает рельсы без `bridge` → клетки пересечения `Road` без `Rail`, по обе стороны рельсы на месте;
  - пешеходный путь и `Crossing` через рельсы → клетки `Sidewalk` / `Crosswalk` без `Rail`;
  - рельсы на мосту (`isBridge`) остаются `Rail|Bridge` (класс доступа `Obstacle`);
  - `railway=tram` не растеризуется, `tramSkipped` считается;
  - `railClearedByLinear` равен числу снятых клеток; клеток `Road|Rail` без `Bridge` нет;
  - порядок обхода и перестановка входа не меняют `dataHash`.
- Реализовать в `CityRasterizer`: шаг `Railway` между водой и дорогами, снятие `Rail` в шагах 3–4, `tram`-фильтр, счётчики в статистике и в сводке bake.
- **Модель (ADR-001 v1.3):** добавить `RailwayKind` в `Railway` (парсер/билдер, `CityModelAsset`, канонические байты — `int32` после `osmId`). Тест: разбор значений `railway=rail|light_rail|subway|tram|narrow_gauge|прочее` в `RailwayKind`. Модель района переимпортировать.
- Золотые хэши (`modelDataHash`, `dataHash`, `accessHash`, при добавлении поля — `settingsHash`) в тестах обновить; таблица «было → стало» в рапорте.
- **Критерий:** тесты зелёные; сборка чистая. Самоприёмка.

### 4C — диагностика связности (test-first)
- Тесты (красные до реализации) по ADR-003 §4.1:
  - синтетика «две улицы и пешеходный переход»: `StrictPedestrianMask` без `Crosswalk` — 2 компоненты, с ним — 1, группа клеток `Crosswalk` помечена как соединяющая;
  - синтетика «тротуарная линия через проезжую часть без `Crosswalk`»: `PedestrianMask` — 1 компонента, `StrictPedestrianMask` — 2; клетки учтены как «неотмеченное пересечение»;
  - гистограмма островов на заданном наборе компонент;
  - концы перехода — по двум конечным вершинам `Walkway(Crossing)` и радиусу `crosswalkEndSearchRadius` (3,0 м, новое поле `CityBakeConfig`, в `CanonicalBytes()`); тесты на все четыре статуса: «оба конца в одной компоненте», «соединяет разные», «один конец без тротуара», «оба конца без тротуара»;
  - перекрёстная проверка по клеткам: группа `Crosswalk` «соединяет», если соседних id компонент ≥ 2.
- Реализовать в Core, вывести в `Analyze Access` и в `analysis_access.md` (новые разделы по ADR-003 §4.1).
- **Критерий:** тесты зелёные. Самоприёмка.

### 4D — перебейк и отчёт
- Перебейк района, `Analyze Access`, обновить PNG в `DOC/reports/img/`: `access.png`, `components_pedestrian.png`, `components_zombie.png`, кроп 400×400 переезда Prinzenallee / рельсов около (88; 49) при 1 клетка = 3–4 px. (Кропы можно делать окном просмотра; TASK-005 ускорит это, но не блокирует.)
- Рапорт `DOC/reports/REPORT-004.md` по шаблону протокола с цифрами:
  - `railClearedByLinear`, `tramSkipped`, клеток `Rail` до/после, клеток `Road|Rail` после (ожидание: 0);
  - компоненты `PedestrianMask`, `StrictPedestrianMask` (без/с `Crosswalk`), `ZombieMask`: число, 10 крупнейших (м², доля);
  - для каждого из 11 переходов: клетки, id компонент `StrictPedestrianMask` на концах, соединяет ли разные; **перепроверить строку перехода osmId 1004914197** (в прежнем ответе Cursor оператору стояло «id 2 | id 10», хотя компонента 10 лежит в другом месте; в `REPORT-003.md` такой строки нет);
  - неотмеченные пересечения (клетки, кластеры, топ-10 с координатами);
  - гистограмма островов; сколько из 108 прежних островов исчезло/остаётся и почему (ожидание: большая часть — щели между рельсами);
  - если крупнейшая компонента `ZombieMask` < 90 % проходимой площади — перечислить 3 крупнейшие и **что их разделяет** (слой и координаты разделяющей полосы).
  - `dataHash`, `accessHash`, `settingsHash`: было → стало.
- Справка: в районе все четыре `Railway` — `Tram` (подтверждено в ходе 4B), поэтому `railClearedByLinear` на этих данных ожидаемо 0, а клеток `Rail` нет совсем; правило «дорога/путь снимает `Rail`» подтверждается синтетическими тестами. В 4A достаточно таблицы тегов четырёх ways (`railway`, `service`, `usage`, `electrified`, `layer`, длина в районе). Прежнее число `Road|Rail` = 100 привести как «до» для сравнения.
- В рапорт приложить `git log --stat` по ветке с порядком «тесты → реализация» для 4B и 4C.
- **Критерий:** ветка запушена в `origin`, рапорт полный. Самоприёмка.
