# TASK-002 — CityModel → растры (фаза P2)

- **Модель:** Grok (2E — Composer)
- **ADR:** `DOC/adr/ADR-002-city-rasterization.md` (читать целиком) и `ADR-001` §3–§5
- **Ветка:** `task/002-rasterization` от `main` (после слияния `task/001-osm-citymodel`; если слияния ещё нет — спросить оператора)
- **Приёмка:** подшаги — самоприёмка; **2G — независимое ревью**; итог — архитектор.
- **Перед началом:** прочитать `DOC/AGENT_PROTOCOL.md`, `DOC/PLAN.md`.

## Цель

Растеризатор в Core + `CityBakeAsset` + меню Bake + экспорт слоёв в PNG для визуальной проверки. Классы доступа и окно просмотра — TASK-003 (P3), не здесь.

## Вне объёма

Классы доступа, генерация тротуаров по `sidewalk=*` (`SidewalkGenerated`), сцена, меши, DI, агенты, поля.

## Правило test-first (обязательное, проверяется по `git log`)

Для 2B и 2C: **отдельный коммит с тестами идёт раньше коммита с реализацией**, `[TASK-002/2B-tests]` → `[TASK-002/2B]`. Тесты выводятся из ADR-002 §3–§4 и §8, а не из кода; перед коммитом реализации убедиться, что они красные. Расхождение теста и ADR — вопрос оператору, а не правка теста «под код». Один коммит «тесты+код» = нарушение, фиксируется в рапорте.

## Подшаги

### 2A (Grok) — типы и сетка
- В **Core**: `CityGrid` (readonly struct, `origin`, `cell`, `w`, `h`, конвертации мир↔клетка, `InBounds`, построение по bbox модели — ADR-002 §2), `CellFlags : ushort` (биты ADR-001 §5.1, включая `Shared = 1<<14`).
- В `CityBakeConfig`: поля `railwayWidth` (3.0), `gateRadius` (1.5); включить в `CanonicalBytes()`, обновить золотые значения хэшей в тестах (старое → новое в рапорте). Ассет `CityBakeSettings` и `map`-модель при необходимости переимпортировать.
- Сверить с кодом P1 семантику `sidewalkMode` (ADR-002 §11). Если расходится — `ADR-change-request`.
- **Критерий:** компиляция без новых предупреждений; тесты на `CityGrid` (конвертации туда-обратно, границы, размер для известного bbox) зелёные. Самоприёмка.

### 2B (Grok) — примитивы растеризации (test-first)
- Core: растеризатор в режимах A и B (ADR-002 §3): заливка кольца с дырами (scanline, even-odd, по центрам клеток), капсула-линия режим A, консервативная линия режим B. Операции над `ushort[]` по индексу `i + j·w`.
- Тесты — ADR-002 §8 (площадь, even-odd, линии, барьер без 8-протечек на случайных линиях с фиксированным seed).
- **Критерий:** все тесты зелёные; тест «барьер» проходит на ≥ 200 случайных линиях. Самоприёмка.

### 2C (Grok) — нанесение слоёв (test-first)
- Core: `CityRasterizer` — применяет шаги 1–9 ADR-002 §4 в заданном порядке; `buildingId` и таблица зданий (§5); статистика (клеток по каждому биту, число клеток-конфликтов зданий, зданий с 0 клеток, клеток под мостами, объектов вне сетки, клеток с `Road|Crosswalk`).
- Детерминизм: порядок `(вид, osmId)`; `dataHash` по §6.
- Тесты: все случаи ADR-002 §8 (порядок наложения, проходы, мосты, ворота, туннели, обрезка, перекрытие зданий, детерминизм и перестановка порядка на входе).
- **Критерий:** тесты зелёные; на синтетическом мини-«кварталe» (дорога + тротуары + здание с двором + переход + барьер с воротами + мост) эталонная карта битов совпадает с ожидаемой. Самоприёмка.

### 2D (Grok) — ассет и Bake
- `CityBakeAsset` (`Assembly-CSharp`) по ADR-002 §6; перезапись на месте (стабильный GUID).
- Меню `ZombieCity/City/Bake Grid...` (по `CityModelAsset` и `CityBakeSettings`): прогресс-бар, сводка `[City]` одним блоком: размер сетки, клеток по каждому биту, площади в м² (клетки·cell²) по слоям, число зданий / с 0 клеток / конфликтов, клеток под мостами, время, `dataHash`.
- `ICityMap` и реализация поверх `CityBakeAsset` (ADR-001 §6; без Extenject).
- **Критерий:** два прогона подряд — одинаковый `dataHash`; время bake района < 5 с целевое (Release-режим Editor указать, провал при > 20 с). Самоприёмка.

### 2E (Composer) — PNG-экспорт слоёв
- Меню `ZombieCity/City/Export Layers PNG...`: PNG сетки 1 клетка = 1 пиксель (север сверху), цвета по приоритету бит: `Building` `#3A3A3A`, `Water` `#2E7DFF`, `Barrier` `#FF7A00`, `Gate` `#FFE000`, `Rail` `#9A4DFF`, `Crosswalk` `#FFFFFF`, `Sidewalk`/`Cycleway`/`Steps` `#C8C8C8`, `Road` `#5A5A5A`, `Green` `#3FA34D`, пусто `#101010`, `Bridge` — рамка/оттенок `#00D1C1` поверх. Дополнительный PNG `buildingId` (хэш id → цвет).
- Файлы в `DOC/reports/img/raster_flags.png`, `raster_buildings.png`.
- **Критерий:** PNG визуально соответствует плану района (двор с дырой, переходы). Самоприёмка.

### 2F — (исключено)
Генерация тротуаров по `sidewalk=*` не делается (ADR-002 §9).

### 2G (Grok, **новая сессия с чистым контекстом**) — независимое ревью
- Исполнитель читает только ADR-001, ADR-002 и эту задачу, **не читает код растеризатора до написания тестов**.
- Пишет собственные граничные тесты по ADR-002 (минимум 15 случаев: линии под малым углом, линия по границе клеток, кольцо точно по центрам клеток, дыра касается дыры, барьер диагональю через угол, ворота у стены, мост над мостом, проход под зданием у границы сетки, нулевая ширина, объект целиком вне сетки и т. п.), запускает их, **код продакшена не правит**.
- Результат — `DOC/reports/REVIEW-002.md`: список проверенных случаев, найденные расхождения с ADR (с минимальным воспроизводящим примером), вывод «принять / исправить».
- Исправления делает основная сессия отдельными коммитами `[TASK-002/fix]`, затем ревьюер перепроверяет.
- **Критерий:** нет открытых расхождений. Самоприёмка по REVIEW-002.

## Definition of Done (проверяет архитектор)

1. Сборка чистая; `asmdef` по-прежнему ровно два; Core без UnityEngine.
2. Все тесты зелёные (число в рапорте); в `git log` порядок «тесты → реализация» соблюдён для 2B и 2C (или нарушение явно отмечено).
3. `dataHash` стабилен между двумя bake; оба значения в рапорте. Обновлённые золотые хэши — таблица «было → стало».
4. Сводка bake в рапорте: размер сетки, клетки по битам, площади слоёв в м², здания (всего / 0 клеток / конфликты), клетки под мостами, время, CPU и режим Editor.
5. Сверка с векторной моделью: суммарная площадь зданий в клетках vs сумма площадей контуров модели (допуск ±2 %); длина дорог·ширина vs площадь `Road` (порядок величины; расхождение объяснить перекрытием со зданиями/тротуарами).
6. PNG слоёв приложены; на них виден план района без явных артефактов (контуры зданий, переходы, барьеры).
7. `REVIEW-002.md` — «принять».
8. Рапорт `DOC/reports/REPORT-002.md` по шаблону, ветка запушена.

## Заметки

- Район мал (≈ 340×242 м, ≈ 680×484 клеток при 0,5 м) — bake должен быть почти мгновенным.
- Не использовать `Dictionary`/`HashSet` порядок в выходных данных.
- Если в районе нет объектов нужного вида (например, мостов), логика покрывается синтетическим тестом; в рапорте это указать явно.
