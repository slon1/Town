# ADR-003 — Классы доступа, анализ связности, просмотр слоёв

Статус: **Принято** (v1.1: диагностика переходов и островов). Охватывает фазу P3 (майлстоун M1). Уточняет ADR-001 §5.4: при расхождении приоритетна эта редакция.

## 1. Область

Из растра `flags` (ADR-002) получается производный растр `access` — разметка «где тротуар, где проезжая часть, где препятствие». Добавляются проверки качества карты (связность, острова) и Editor-просмотр слоёв. Агенты, поля и фреймворк по-прежнему вне объёма.

## 2. Классы доступа

`CityAccess : byte`:

| Значение | Имя | Смысл (для будущих агентов) |
|----------|-----|------------------------------|
| 0 | `Obstacle` | непроходимо для всех |
| 1 | `Roadway` | проезжая часть: доступна **только зомби** |
| 2 | `Pedestrian` | доступна всем: тротуары, переходы, велодорожки, лестницы, проходы, зелень, открытые места |

Правило (проверять сверху вниз, по `CellFlags` клетки):

1. **`Obstacle`**, если выставлен **любой** из `Building`, `Water`, `Barrier`, `Rail`.
   Исключения (`Gate`, `BuildingPassage`, `Bridge`) уже разрешены растеризатором (ворота снимают `Barrier`, проходы снимают `Building`, мост снимает нижние слои, ADR-002 §4), поэтому в классификаторе отдельных исключений нет. Клетка `Rail|Bridge` — это рельсы на мосту, она остаётся `Obstacle`.
2. **`Roadway`**, если выставлен `Road` и **не** выставлен ни один из `Sidewalk`, `SidewalkGenerated`, `Crosswalk`, `Steps`, `Cycleway`, `Shared`.
   Дорога под мостом/на мосту (`Road|Bridge`) — `Roadway`. Проезд сквозь здание (`Road|BuildingPassage`) — `Roadway`.
3. **`Pedestrian`** — всё остальное (клетка без битов, `Green`, `Sidewalk`, `Crosswalk` поверх `Road`, `Shared` и т. д.).

Принятые решения: переход — зона пешеходов; велодорожка — `Pedestrian`; смешанная улица (`Shared`) — `Pedestrian`; конфликт «`Road` + явный `Sidewalk`» — `Pedestrian`.

Доступность по классам агентов (для будущего, здесь не реализуется): житель = `Pedestrian`; зомби и солдат = `Pedestrian` + `Roadway`.

## 3. Хранение

- `CityBakeAsset` получает `byte[] access` (один байт на клетку) и `accessHash` (FNV-1a 64, как в ADR-001 §4).
- `dataHash` из ADR-002 **не меняется** (он покрывает grid → flags → buildingId → таблицу зданий), чтобы золотые значения тестов остались прежними. `access` — производные данные, пересчитываются из `flags` детерминированно.
- `ICityMap` (ADR-001 §6) получает `CityAccess GetAccess(int i, int j)`.
- Классификатор — чистая функция в Core: `AccessClassifier.Classify(CellFlags) : CityAccess` и массовая версия `ClassifyAll(ushort[] flags, byte[] access)`.

## 4. Анализ связности (Core, без Unity)

Входной растр `access`. Связность по **8 соседям** (ходьба по диагонали допустима), при этом диагональный ход запрещён, если обе смежные ортогональные клетки — `Obstacle` (нельзя «просачиваться» между двумя углами препятствий). Это правило должно совпадать с гарантией барьерной растеризации (ADR-002 §3, режим B).

Считаются связные компоненты для двух «масок проходимости»:

| Маска | Клетки |
|-------|--------|
| `PedestrianMask` | `access == Pedestrian` |
| `ZombieMask` | `access ∈ {Pedestrian, Roadway}` |

Отчёт (в консоль блоком `[City]` и в файл отчёта):
- число компонент, размер (клеток и м²) и доля от проходимой площади для каждой из N крупнейших;
- число «островов»: компонент размером < `islandMinCells` (по умолчанию 200 клеток = 50 м²) — список из 10 крупнейших островов с мировыми координатами центра;
- **эффект переходов:** число компонент `PedestrianMask` при расчёте **без** клеток `Crosswalk` и **с** ними; число клеток `Crosswalk`, соединяющих разные компоненты (то есть переходов, реально связывающих тротуары через проезжую часть);
- клетки `Road|Rail` (железнодорожные переезды): число и координаты (они дают `Obstacle` и режут улицу);
- доля клеток по классам доступа.

Параметр `islandMinCells` — в `CityBakeConfig` (в `CanonicalBytes()`; золотые хэши настроек обновить).

Параметр `crosswalkEndSearchRadius` (по умолчанию **3,0 м**) — в `CityBakeConfig` и в `CanonicalBytes()`.

### 4.1. Диагностика переходов и островов (v1.1)

Метрика «Crosswalk effect» по `PedestrianMask` недостаточна: явные тротуарные линии (`Sidewalk`) перекрывают `Road` и дают класс `Pedestrian` (§2), поэтому тротуары связаны через проезжую часть и без клеток `Crosswalk` (в районе получилось 116 / 116). Добавляются:

- `StrictPedestrianMask` = `access == Pedestrian` **и** бит `Road` не выставлен. Компоненты считаются без клеток `Crosswalk` и с ними (клетки `Crosswalk` имеют бит `Road`, поэтому добавляются явно).
- Концы перехода берутся не по клеткам группы, а по **двум конечным вершинам** линии `Walkway(Crossing)` из модели (соседние переходы на перекрёстке могут слиться в одну группу клеток, и у такой группы нет осмысленных «концов»). Для каждого конца ищется ближайшая клетка `StrictPedestrianMask` в радиусе `crosswalkEndSearchRadius`. Результат на конец: id компоненты и расстояние до неё, либо «нет тротуара рядом». Статус перехода: «оба конца в одной компоненте», «соединяет разные» (id различаются), «один конец без тротуара», «оба конца без тротуара».
- Перекрёстная проверка по клеткам: 8-связная группа клеток `Crosswalk` **соединяет**, если множество id соседних компонент `StrictPedestrianMask` имеет размер ≥ 2.
- «Неотмеченные пересечения»: клетки `Road` + (`Sidewalk` или `SidewalkGenerated`) без `Crosswalk`: число клеток, число 8-связных кластеров, 10 крупнейших с координатами.
- Гистограмма размеров компонент: ≤ 10 клеток, 11–50, 51–199, ≥ 200.

Правила классификации (§2) не меняются.

## 5. Просмотр слоёв (Editor)

Окно `ZombieCity/City/Layers Viewer`:
- слои: `Access` (палитра ниже), `Flags` (палитра TASK-002/2E), `BuildingId`, `Components` (случайный стабильный цвет на компоненту; переключатель Pedestrian/Zombie маски);
- масштаб колёсиком, панорама перетаскиванием, курсор показывает: клетка (i, j), мировые метры (x, z), имена выставленных битов, `access`, `buildingId` и `osmId` здания;
- кнопка «Export PNG» для текущего слоя.

Палитра `Access`: `Obstacle` `#202020`, `Roadway` `#D04040`, `Pedestrian` `#40C080`; границы компонент на слое `Components` не рисуются.

Окно использует `CityBakeAsset` и не меняет данные.

## 6. Принятые упрощения

- 4-связность и ширина проходов (clearance) не анализируются: агентов пока нет.
- Тротуары без пересечений, внутренние дворы без выхода и подобные островки не «чинятся» автоматически; они только отмечаются в отчёте. Решение о правках данных принимает оператор.
