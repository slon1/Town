# PLAN — общий план проекта (рабочее название: ZombieCity)

Статус документа: **v2** (после решений оператора). Обновляется архитектором; исполнители отмечают только чекбоксы статуса в разделе 3.

## 1. Цель текущего прототипа

Из `.osm`-файла реального района строится город в Unity:
- здания как экструзия реального контура с высотой из OSM;
- пешеходные и транспортные зоны разделены и размечены (где тротуар, где проезжая часть);
- результат запекается в растровые слои, пригодные для будущей симуляции.

**Вне объёма (до решения оператора по итогам прототипа):** фреймворк частиц, агенты, поля управления, сетка солдат, спавн. Решение «добавлять ли фреймворк и агентов» принимает оператор после приёмки M2.

Семантика доступа (для будущего, закладывается только в разметке): здания, вода, барьеры, рельсы — непроходимы; **проезжая часть доступна только зомби**; тротуары, переходы, открытые места, мосты для пешеходов — для всех.

## 2. Архитектурные принципы

1. **Bake offline, runtime читает только растры.** Парсинг OSM и растеризация — в Editor.
2. **Одна мастер-сетка `CityGrid`.** Всё привязано к ней.
3. **Детерминизм.** Один `.osm` + одни настройки = побитово одинаковые ассеты.
4. **Core без UnityEngine** — обеспечивается отдельным `asmdef` с `noEngineReferences` (см. протокол).
5. **Сцена минимальна:** Ground quad с текстурой слоёв, меш зданий, debug-оверлеи.
6. **Каждая фаза даёт видимый результат.**

### 3.1. Заготовка на будущее (не делается сейчас)

При возобновлении работ с агентами растр `Access` и `BuildingId` станут основой для полей: проходимость по классам агентов, стоимость клеток, SDF и градиент от препятствий, openness, clearance под радиус солдата. Мастер-сетка 0,5 м допускает целочисленное огрубление под разрешение фреймворка.

## 4. Структура документации и кода

```
DOC/
  PLAN.md, AGENT_PROTOCOL.md
  adr/ADR-NNN-*.md        — архитектурные решения (источник истины)
  tasks/TASK-NNN-*.md     — задачи для Cursor
  reports/REPORT-NNN.md   — рапорты
  data/                   — описание источника данных (README.md)
  framework/              — зарезервировано под документацию фреймворка

Assets/
  Source/map.osm          — исходный .osm (экспорт с openstreetmap.org)
  _Project/
    City/Settings/        — CityBakeSettings.asset
    City/Baked/           — запечённые ассеты
    Scripts/Runtime/City/Core/   — чистый C# (asmdef ZombieCity.City.Core)
    Scripts/Runtime/City/        — ассеты-контейнеры, рантайм-код
    Scripts/Editor/City/         — импорт, bake, окна, меню
    Tests/EditMode/              — тесты (asmdef)
    Scenes/
    ThirdParty/                  — вендорные библиотеки
```

**asmdef — только там, где необходимо:** `ZombieCity.City.Core` (изоляция и тестируемость чистого кода) и тестовая сборка. Остальное — штатные сборки. Любой новый `asmdef` требует обоснования в рапорте.

## 5. Риски

| Риск | Митигация |
|------|-----------|
| Экспорт с сайта отдаёт relations без полных членов → неполные мультиполигоны | Парсер терпим к неполноте, счётчик предупреждений в статистике; при большой доле потерь заменить файл на выгрузку через Overpass |
| Тротуары в OSM неполны (`sidewalk=both` без отдельных линий) | Генерация тротуара дилатацией полотна, флаг `SidewalkGenerated` (ADR-001) |
| Туннели/мосты/ж/д в 2D-растре | Туннели исключаются; мосты имеют приоритет; ограничение документируется |
| Extenject 9.2 на Unity 6000.5 | Проверка в P4; при проблемах — рапорт, решение архитектора |
| Размер сетки/память | Мастер-сетка параметризована; тайлинг — отдельный ADR при росте карты |

## 6. Решения оператора

1. `asmdef` разрешены там, где необходимо.
2. Файл района: `Assets/Source/map.osm`, экспорт напрямую с openstreetmap.org. Замена на Overpass — только если в статистике будет много неполных мультиполигонов.
3. Render pipeline: **URP**.
4. Фреймворк и агенты **пока не используются**. Сейчас только загрузка и разметка города.
5. Сетка солдат и поля — не делаем.
6. Здания: экструзия реального контура, высота из OSM.
7. Здания непроходимы.
8. Вода (канал Panke) — препятствие; мосты проходимы.
9. Проезжая часть доступна только зомби; нужна разметка «тротуар / проезжая часть».
10. Git: ветка на задачу, слияние после приёмки архитектора.
11. Язык документации — русский.

### Решения архитектора (v2.1, по вопросам Cursor)
1. Пешеходные переходы — зона пешеходов (`Pedestrian`), несмотря на `Road` под ними. **Принято**, внесено в ADR-001 §5.4.
2. `highway=track` — `Walkway` (path, 3 м), кроме `motor_vehicle=yes|designated` — тогда `Road`.
3. `highway=living_street` — `Road` с признаком `isShared`; в растре бит `Shared`, класс доступа `Pedestrian`.
4. Велодорожки — `Pedestrian`.
5. Водные линии (`canal|river|stream`) — отдельная сущность `Waterway` в модели; растеризация в P2 шириной `waterwayWidth`.
6. `building:part` — игнорируется со счётчиком (для прототипа достаточно).
7. Основная ветка — та, что указана в `origin/HEAD`; исполнитель определяет её (`git symbolic-ref refs/remotes/origin/HEAD`) и указывает в рапорте.
8. Хэш настроек — по явному каноническому представлению семантических полей (без GUID и данных Inspector).
9. Меню Import: дефолт `Assets/Source/map.osm`, можно сменить; последний выбор — в `EditorPrefs`.
10. Gizmo — отдельный Editor-drawer (`[DrawGizmo]` в папке `Editor`), без `#if UNITY_EDITOR` в рантайм-коде.
11. Порог замены файла на Overpass-выгрузку: **>10 %** неполных мультиполигонов (здания/землепользование).
12. `sidewalk=*` на дороге — только `sidewalkMode`; отдельные `Walkway` не создаются, тротуар генерирует P2.

### Решения архитектора (v2.2, приёмка P1)
13. Генерация тротуаров по `sidewalk=*` отложена: в районе нет дорог с `sidewalkMode Left/Right/Both`, все тротуары — отдельные линии (ADR-002 §9).
14. Test-first (отдельный коммит с тестами раньше реализации) обязателен с P2; в P1 не соблюдён (зафиксировано).
15. Независимое ревью растеризатора (подшаг 2G) в чистой сессии Grok.
16. P2 принят. Расхождение площади зданий −21,6 % объяснено обрезкой по `<bounds>`: для 47 зданий целиком в сетке Δ = +0,004 %; для граничных проверка в 3A.
17. Классы доступа (ADR-003): `Obstacle` = любой из `Building|Water|Barrier|Rail`; `Roadway` = `Road` без пешеходных/смешанных битов; остальное `Pedestrian`. Исключения мостов/проходов/ворот уже учтены растеризатором.
